# dsh 全功能体检 — 检测命令（单独版）

在 NAS 上（SSH 或 fnOS 终端）执行下面任一命令即可：

## 方式一：直接跑仓库里的脚本（推荐）

```bash
# 只读体检（不改任何东西，看 PASS/WARN/FAIL 汇总）
sh scripts/check-dsh.sh

# 自动修复能安全修的权限/属主项
sh scripts/check-dsh.sh --fix
```

## 方式二：一键粘贴（不依赖仓库文件，单条命令跑完）

```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/tanging22/dsh-fnos-console/main/scripts/check-dsh.sh)" 
```

（若网络不通 GitHub，就用方式一，把脚本文件拷到 NAS 上跑）

## 方式三：只想快速看「dsh 用户能不能读配置/工作目录」这一项

```bash
# 定位 dsh home（面板数据目录下的 home，或 workspace.active 里写的路径）
DSH_HOME="/vol1/@appdata/fnos-dsh-manager/home"
# 看属主和权限位
ls -ld "$DSH_HOME" "$DSH_HOME/profiles" "$DSH_HOME/storages"
# 看面板进程是谁在跑（uid）
ps -eo user,uid,cmd | grep dashboard.js
# 实测面板身份能不能读
su -s /bin/sh - "$(ps -eo user,cmd | awk '/dashboard.js/{print $1; exit}')" -c "test -r '$DSH_HOME' && echo 可读 || echo 不可读"
```

## 脚本查什么（9 节）

1. 面板进程 + 28001 端口
2. node/npm 运行时
3. dsh 安装与二进制
4. **dsh 用户读配置/工作目录权限（重点）**：home/profiles/storages/数据目录的 owner、mode、读写进入，并实测面板身份能否读
5. 凭据文件 600 权限
6. webserver 配置补丁（通配绑定检测）
7. dsh 端口占用
8. dsh 进程树 + 内存
9. 面板 API 直连探测

结尾给 `PASS/WARN/FAIL/SKIP` 汇总，有 FAIL 则退出码 1。
